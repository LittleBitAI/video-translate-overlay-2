# Library redesign settled and shipped in PR #9: side rail plus grid on PC, playlist expands in place on phone, edit mode, thumbnails, one shared menu

The user called the library (보관함) screen sloppy. The 영상 열기 / 설정 buttons appeared unexpectedly in the top bar, the playlist arrows were unexplained, and clicking a playlist showed no videos. The user wanted a playlist click to show its videos with title and thumbnail, and genuinely different PC (landscape) and mobile (portrait) layouts. The assistant reviewed captures, then proposed five design choices. The user accepted the recommended option for all five, and the work shipped as PR #9: 11 completion conditions passed, merged at round 3 with 0 P2 remaining.

## Decisions

- PC layout: a side rail of playlists beside a grid of video cards — The user said PC is landscape and mobile is portrait, so the layout itself must differ, not be a wrapped version of one column (rejected: The previous single phone-shaped column stretched to desktop width)
- Phone layout: the tapped playlist expands to show its videos directly under its row — The user asked that tapping a playlist show its videos, titles and thumbnails right below it (rejected: Revealing a management form below the list, with the videos pushed off-screen)
- Navigation: one shared 영상 / 보관함 / 설정 menu in the same place on every screen — The user found it unexpected that the top bar swapped to 영상 열기 / 설정 buttons on entering 보관함 (rejected: A top bar whose contents change per screen)
- Editing: management controls (rename, delete, add, reorder, full URL) move behind an edit mode, out of the default view (rejected: A management form that opens when a playlist is clicked; bare ↑ ↓ reorder buttons in the default view)
- Thumbnails: YouTube thumbnails now, a designed placeholder for other sites

## Facts

- PR #9 merged: activating a playlist immediately shows its videos as thumbnail cards (beside it in the side rail layout on wide windows, under the tapped row on phones), management sits behind edit mode, and one shared 영상 / 보관함 / 설정 menu appears on every screen; 11 completion conditions passed, round 3, 0 P2 left
- For YouTube the stored video key is the YouTube video ID, so the thumbnail address can be derived on the screen with no backend work (assistant's inference from the key format) (unverified)
- Non-YouTube sites store only a hash of the URL, so they have no thumbnail image source (unverified)
- The backend returned video duration even before the redesign, but the old screen did not show it (unverified)
- Before the change, the backend accepted a playlist move of exactly one place per request (unverified)
- Device sync sends absolute positions (unverified)
- The Windows app window in the 2026-11-15 recorded capture was 1,009 px wide (unverified)
- The registered Windows and Android library checks click controls by their names, so a UI rename breaks them and they must be rewritten and rerun (unverified)
- The library design is described in DESIGN.md, docs/design/frontend.md and README.md, and these had to be rewritten for the redesign (unverified)
- The approved design uses a charcoal palette and a 14/16/20/28 type scale (unverified)
- Behaviour to preserve: named delete confirmation, no automatic translation when a video opens, account separation, and reordering that does not require drag gestures (unverified)

## Preferences

- Look at the actual rendered UI yourself ("ui를 봐서" ... "봐라") instead of judging from code
- PC and mobile must have different layouts at the structural level (레이아웃 "자체"가 달라야한다), with PC landscape and mobile portrait
- Clicking a playlist must show that playlist's videos, titles and thumbnails directly below it
- Avoid unexpected behaviour such as controls appearing in the top bar when a tab is entered
- Use design skill to the fullest (디자인 스킬을 최대한으로)

## Open

- The user never confirmed three assistant calls in the spec: (1) a backend exception so one request can move a playlist several places, to support a drag handle, instead of only labeled 위로 / 아래로 buttons; (2) the PC layout starting at 768 px rather than 1024, so a phone held sideways also gets the side rail; (3) cards showing the site name instead of the raw URL, with the full address only in edit mode, which rewrites the design record rule that links must not hide their destination
- The spec asked the session to confirm that device sync still works with multi-place moves; the transcript does not record the result
- The assistant asked whether the charcoal palette and type scale should be reopened; the user did not answer
